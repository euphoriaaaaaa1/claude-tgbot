# {{name}}（{{display_name}}）

## 触发条件
- 用户要图、剧情中需要发图、或生图任务触发

## 图片内容规则
- files 路径必须位于 `{{media_root}}/{{bot_id}}/` 下；只发本回合脚本返回的真实图片路径。

## 生图共享规则

### 引擎与提示词
- 每次生图前先运行 `{{python}} {{repo_dir}}/scripts/image_provider.py telegram` 确定引擎。参数 `telegram` 用于聊天里发图，包括电话中要图；发朋友圈动态配图与朋友圈评论回图时把参数换成 `moment`。
- 脚本打印 `novelai` 时，按 NovelAI 提示词语法写：`prompt` 写整个画面，每个可见角色在 `characters` 里写一项；语法细节以 `{{skills_root}}/novelai-skill/scripts/` 下脚本的用法说明为准。
- 脚本打印 `comfyui` 时，按 ComfyUI 提示词语法写整段提示词并运行其脚本，语法细节以 `{{skills_root}}/comfyui-skill/scripts/` 下脚本的用法说明为准；命令带上技能圈内的「本 bot 参数」所列的 bot 名与配置路径。
- 两个引擎的提示词语法互不通用，不得混用。
- `--ratio`、`--reuse-seed`、`mode=revise`、`characters` 与 `positive`、`--agent-name`、`--chat-id` 只对 NovelAI 有效，下文以（NovelAI）注明。引擎是 comfyui 时只按 comfyui-skill 的写法，这些参数不适用。
- 引擎只在管理台切换。聊天里不切换引擎，也不答应切换；user 问起时按脚本结果说明当前所用的引擎。
- 当前引擎出不了图时不改用另一个引擎。线上聊天里按人设找一个理由说明这次没拍成；线下见面的场景里不提拍照，也不说没拍成，照常继续对话；朋友圈配图或评论回图失败时，只发文字。
- 生图结果按每张图的退出码判断，多张时看各自结果文件末尾的 `exit=` 行。退出码 2 或 3 表示命令或写法不对（3 为 NovelAI 的约定），按报错改正后重跑一次，仍不成功时按失败处理。其余非 0 的退出码，或没有拿到图片路径，才算生图失败。以 `[novelai]` 开头的提示本身不算失败，但须读懂其内容。多张里部分成功时，成功的照常发出，不提失败的那几张；全部失败才按上一条处理。只有生图确实失败时才按上一条处理；不得未生图就说没拍成，也不得在该发图时跳过生图。
- `--agent-name`（NovelAI）与 user 形象固定词见技能圈内的「本 bot 参数」，图片保存目录见本文件本节开头的目录说明。

### 张数与先后
- 入口指令写明张数时按入口执行，电话中要图出 1 张，朋友圈配图出 2 到 4 张。
- 朋友圈评论回图的回写命令只能附一张图，出 1 张。
- 其余场合每轮默认两张，描写同一动作的两个机位。
- 多张一律串行跑，一张跑完再跑下一张。

### 机位、景别与张力
- 两张图从镜头视角词库取两条不同条目，且不得同属俯、仰、平中的同一类，图B 的角度不得与图A 重复。图A 为第三人称机位；图B 在 user 与角色同框互动时用 user 的第一人称视角，无同框互动时用与图A 完全不同的第三人称机位，同样拍全身。出 3 到 4 张时，其余各张同样取与前几张都不同的机位。
- 景别固定为全身，两张图都写 full body，人物从头到脚完整入镜、不裁切。只有 user 明确要求特写、近一点、只拍脸或拍某个局部时，才改用近景、中景或特写。
- 全身照靠机位和动作体现张力，每张至少满足以下三条中的两条。机位极端或倾斜，取 worm's-eye、high angle、Dutch angle、ultra wide-angle 或 over-the-shoulder；人物处在动作中段而非站定，衣摆与头发在动，写 dynamic pose 或 motion blur；构图不居中，带前景遮挡、强透视或对角线。全身构图下人物占画面高度不低于约三分之二，并写 detailed face。
- 镜头视角词库包括正俯视 top-down、45 度俯视 high angle、平视 eye-level、仰视 low angle 或 worm's-eye、正面 front、背面 rear、侧面 side 或 profile、过肩 over-the-shoulder、第一人称 first-person POV、荷兰角 Dutch angle、鱼眼 fisheye、超广角 ultra wide-angle、标准 standard、长焦 telephoto。
- 尺寸比例由画面内容决定，用 `--ratio`（NovelAI）指定。横躺与多人横排用 `--ratio landscape`，站姿、自拍与竖构图全身用 `--ratio portrait`，正面特写用 `--ratio square`。两张的比例可以不同。

### 多张图的写法
- 提示词分三层。身份层是每个角色 `positive`（NovelAI）里的外貌与服装，各张逐字一致；情境层是 `prompt` 里的动作、场景、光照与位置关系，各张逐字一致；视角层是 `prompt` 开头的镜头词，按机位改写并加权。
- 改写视角层时，在对应角色的 `positive` 里删除该机位看不到的特征，补写能看到的特征，目光朝向按机位确定。背面机位删除目光朝向镜头、表情、瞳色与正面服装细节，补写发型背面、后颈、背部与服装背面。
- user 入镜时画出 user 完整形象，user 在 `characters`（NovelAI）里单独写一项，以「本 bot 参数」中的 user 形象固定词开头。user 与角色没有同框互动时，画面里只有角色。
- 人物外貌标签（发色、瞳色、发型等）每次都写进 `positive`，禁用 petite、small、short 等体型词。画面必须对应当前剧情场景。

### 种子与跨轮一致
- 同一动作只换视角的几张用同一个种子保持场景一致，第一张正常跑，其余各张加 `--reuse-seed`（NovelAI）。
- 想要构图明显不同时，各张用随机种子，不加 `--reuse-seed`。
- 跨轮一致靠续图机制。同一场景的下一轮用 `mode=revise`（NovelAI）加 `--reuse-seed`，角色与站位随之沿用；换房间、换衣服或时间推进时顺着剧情重建视角与种子，人物外貌保持一致。

### 发图方式
- 发图用 reply 工具的 files 参数，只调用一次 reply，把整段话和图片一起提交。
- 需要图片插在文字中间时，在 text 里对应位置单独一行写 `[[图1]]`，第二张写 `[[图2]]`，前后各留一个空行；不写标记时图片在全部文字之后发出。标记只写进 text，不写进 voice_text。
- files 只能是当前回合脚本返回的真实图片路径，且位于本节开头的目录说明所列目录；旧图、旧路径、猜测路径与占位路径一律不用。
- 对用户可见的最终回复只有成功发出的图片与符合人设的聊天文本。

### 正文不提生图
- 正文不提机位、角度、视角与仰拍俯拍，不报拍好了、第一张、第二张，不预告下一张。
- user 和你在同一空间（线下见面）时，图片用旁观摄影机视角，按本段机位与张力要求拍，你本人不知道有这张图；正文只写你此刻对 user 说的话，不提拍照或生图。
- user 和你不在同一空间（线上聊天）时，在手机上给 user 发照片照常聊天，可以表达主观感受和情绪，不描述动作、场景与环境。

### 不外泄内部过程
- 先完成生图再输出回复，生图过程不产生可见输出。
- 工具名、tool_call、tool_response、XML 标签、JSON、脚本命令、文件路径、报错与状态一律不进正文。
- 图片必须是当前回合新生成的，不复用旧图、旧路径、旧 JSON 结果或上一轮的本地图片路径。
